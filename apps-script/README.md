# 구글 시트 연동 설정

사이트의 참가 신청 폼(`index.html` → `#/apply`)을 구글 시트에 연결하는 방법입니다.
아래 3단계를 마치면 **값 2개**가 나오고, 그걸 `index.html`에 넣으면 끝입니다.

설정을 넣기 전까지 폼은 **미리보기 모드**로 동작합니다. 전부 작성해 볼 수 있고,
제출하면 개발자 콘솔에 보낼 내용만 찍힙니다. 시트에는 기록되지 않습니다.

---

## 1. 스프레드시트 준비

응답을 쌓을 스프레드시트를 열고 주소에서 ID를 복사합니다.

```
https://docs.google.com/spreadsheets/d/<<< 이 부분이 ID >>>/edit
```

`웹신청` 탭은 자동으로 만들어지므로 미리 만들 필요 없습니다.
구글 폼 응답 탭에 직접 쓰지 않는 이유는, 폼 제출과 행이 엉키기 때문입니다.

## 2. OAuth 클라이언트 ID 발급

[console.cloud.google.com](https://console.cloud.google.com)

1. 새 프로젝트 생성
2. `API 및 서비스` → `OAuth 동의 화면`
   - User Type: **외부**
   - 앱 이름 / 지원 이메일 / 개발자 이메일 입력
   - 범위는 기본(`email`, `profile`, `openid`)만 — 추가하지 않습니다
   - **앱 도메인**
     | 항목 | 값 |
     |---|---|
     | 애플리케이션 홈페이지 | `https://2026endpoint.github.io/` |
     | 개인정보처리방침 링크 | `https://2026endpoint.github.io/privacy/` |
     | 서비스 약관 링크 | `https://2026endpoint.github.io/terms/` |
     | 승인된 도메인 | `2026endpoint.github.io` |
   - 구글이 **브랜딩 인증**을 요구하면 [Search Console](https://search.google.com/search-console)에서
     `https://2026endpoint.github.io/` 소유 확인이 필요합니다. "HTML 파일" 방식을 고르면 받는
     `googleXXXX.html` 파일을 저장소 맨 위(`index.html` 옆)에 올리면 됩니다.
   - **반드시 "앱 게시"(프로덕션)로 전환**하세요.
     테스트 모드로 두면 미리 등록한 100명만 로그인됩니다.
     이 범위들은 민감 정보가 아니라 구글 심사 없이 바로 게시됩니다.
3. `사용자 인증 정보` → `사용자 인증 정보 만들기` → `OAuth 클라이언트 ID`
   - 유형: **웹 애플리케이션**
   - **승인된 JavaScript 원본**에 배포 주소를 모두 등록
     ```
     https://2026endpoint.github.io
     http://localhost:5500
     ```
   - 승인된 리디렉션 URI는 입력하지 않습니다 (ID 토큰 방식이라 불필요)
4. 발급된 `....apps.googleusercontent.com` 복사

> Google Sheets API 사용 설정은 **필요 없습니다.** Apps Script가 시트를 직접 다룹니다.

## 3. Apps Script 배포

1. 스프레드시트 → `확장 프로그램` → `Apps Script`
2. [Code.gs](Code.gs) 내용을 전부 붙여넣기
3. 맨 위 `CONFIG`를 채웁니다
   ```js
   SHEET_ID : '1단계에서 복사한 시트 ID',
   CLIENT_ID: '2단계에서 복사한 클라이언트 ID',
   ```
4. 함수 선택창에서 `setup` 실행 → 권한 승인 (한 번만)
5. `배포` → `새 배포` → 유형 **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
6. 나오는 `https://script.google.com/macros/s/..../exec` 주소 복사

> 코드를 고칠 때마다 `배포 관리` → `편집` → 버전 **새 버전**으로 다시 배포해야
> 반영됩니다. URL은 그대로 유지됩니다.

## 4. 사이트에 값 넣기

`index.html` 맨 아래 `참가 신청 폼` 스크립트의 `CFG`를 채웁니다.

```js
var CFG = {
  CLIENT_ID: '....apps.googleusercontent.com',            // 2단계
  ENDPOINT:  'https://script.google.com/macros/s/..../exec', // 3단계
  DRAFT_KEY: 'endpoint.apply.v2'
};
```

두 값이 채워지는 순간 미리보기 모드가 풀리고 실제 구글 로그인 버튼이 뜹니다.

## 보안에 대해

웹 앱을 "모든 사용자"로 배포하지만, URL이 알려져도 안전합니다.

- `doPost`가 받은 구글 ID 토큰을 **구글 서버에 직접 조회해 검증**합니다 (`verifyIdToken_`)
- 우리 `CLIENT_ID`로 발급된 토큰이 아니면 거부합니다
- 이메일은 사용자 입력이 아니라 **토큰에서 꺼내 씁니다** → 남의 이메일로 위조 제출 불가
- `ALLOWED_DOMAIN`을 채우면 특정 도메인 계정만 받습니다 (예: `seoultech.ac.kr`)

## 항목을 바꾸려면

폼 항목과 시트 열은 **이름으로** 연결됩니다.

- 폼 항목: `index.html`의 `SCHEMA` 배열에 있는 `k` 값
- 시트 열: `Code.gs`의 `HEADERS` 배열

둘의 이름이 같아야 그 열에 들어갑니다. 열 순서는 자유롭게 바꿔도 되고,
`HEADERS`에 없는 항목은 시트에 기록되지 않습니다.

현재 짝은 다음과 같습니다. 구글 폼 질문과 1:1로 맞춰져 있습니다.

| 번호 | 신청서 항목 | 시트 열 | 형태 |
|---|---|---|---|
| — | (서버가 기록) | 제출시각, 이메일, 계정 식별자 | — |
| 01 | 기본 정보 | 성함, 학번, 학년, 연락처 | 입력 + 단일 선택 |
| 02 | 소속 동아리 | 소속동아리 | 중복 선택 (다락방/PLUM/EC/NL/TCP) |
| 03 | 희망 역할 | 희망역할 | 자유 입력 + 빠른 선택 칩 |
| 04 | 기술 스택 및 개발 경험 | 기술스택 및 개발 경험 | 여러 줄 입력 |
| 05 | 팀 보유 여부 및 팀원 | 팀 보유 여부 및 팀원 | 여러 줄 입력 |
| 06 | 전체 일정 참석 가능 여부 | 전체 일정 참석 가능여부 | 중복 선택 (11/4, 11/11, 모든 일정 참석 가능) |
| 07 | 기타 (하고싶은말) | 기타 | 여러 줄 입력 · **선택 항목** |

`기타`를 뺀 나머지는 모두 필수입니다. 신청서 헤더의 빨간 `*` 가 필수 표시입니다.

## 로컬 테스트

`index.html`을 더블클릭해 `file://`로 열면 구글 로그인이 동작하지 않습니다.

```bash
python -m http.server 5500
# http://localhost:5500 으로 접속
```

이 주소도 2단계의 승인된 JavaScript 원본에 등록되어 있어야 합니다.
